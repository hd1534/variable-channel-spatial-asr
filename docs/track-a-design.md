# Track A 설계 (구현됨, 학습 전)

웹페이지의 Track A를 구현한 내용이다. 사전학습 화자 인코더 없이, Log-Mel과 마이크 쌍 GCC-PHAT만 받는 초경량 Conformer를 처음부터 학습한다.

- 코드: [`models/track_a.py`](../models/track_a.py)
- 설정: [`configs/track_a.json`](../configs/track_a.json), [`configs/track_a_spatial.json`](../configs/track_a_spatial.json)
- 테스트: [`tests/test_track_a.py`](../tests/test_track_a.py)

## 1. 범위

| 항목 | 결정 | 이유 |
|---|---|---|
| 맡는 일 | 시점마다 화자 임베딩을 하나씩 내고, 공통 슬롯 매칭(`models/slots.py`)에 넘긴다 | 다른 시스템과 인터페이스가 같다(`embed(batch) -> [B, 80, D]`). 그래서 학습·검증·본 평가·채점 코드를 그대로 쓴다 |
| 전사 | 공통 Qwen3-ASR이 예측 화자 구간을 받아 적는다 | 페이지 1.1절의 파이프라인이다. 시스템 사이 `cpWER` 차이가 화자 구분에서만 나온다 |
| 사전학습 모델 | 쓰지 않는다 | Track A의 정의다 |
| 학습 데이터 | `train-clean-100` 251명. 다른 시스템과 같은 장면 생성기와 방 800개를 쓴다 | 제안 모델과 비교하려면 데이터가 같아야 한다 |

## 2. 하나의 가중치로 두 관측 범위: 동적 문맥 학습

스트리밍 ASR의 동적 청크 학습(WeNet U2 방식)과 같은 생각이다. 채널 드롭이 마이크 수를 무작위로 바꿔 한 모델이 M = 1~4를 모두 받게 하듯, 학습 배치마다 어텐션이 볼 수 있는 범위도 무작위로 바꾼다.

| 모드 | 어텐션 | 시점 `t_k`에서 읽는 프레임 | 학습 라벨 | 보고 |
|---|---|---|---|---|
| `causal` | 과거 2초까지, 미래는 막음 | `t_k`까지 끝난 마지막 프레임 | 인과 창 `[t_k - 0.25, t_k)`의 화자(`labels`) | 공식 causal 표 (`full` 변형) |
| `full` | 세션 전체 | 공식 라벨 창 `[t_k, t_k + 0.25)` 가운데 프레임 | 공식 창의 화자(`labels_eval`) | `full_audio` 참고 행 (`full_context` 변형) |

- 학습 배치의 절반은 `full`이다(`track_a.full_context_prob = 0.5`).
- 합성곱은 두 모드 모두 인과다(왼쪽만 패딩). 그래서 두 모드는 어텐션이 무엇을 읽는지만 다르다.
- 최고 체크포인트와 임계값은 공식 조건인 `causal` 모드로 고른다. `full` 모드의 임계값은 학습이 끝난 뒤 같은 검증 세트에서 따로 고른다.

## 3. 입력

STFT는 제안 모델과 같다(`n_fft` 512, `hop` 160, 10 ms). 4프레임을 묶어 모델 프레임 하나(40 ms)로 쓴다.

- **Log-Mel 80구간**: 기준 채널(가장 낮은 번호의 활성 채널)에서 뽑는다. 목소리 전용의 ECAPA와 같은 채널이다.
- **GCC-PHAT**: 활성 마이크 쌍마다 지연 ±16표본(33값)을 뽑고, 쌍의 상대 위치 2값을 덧붙인다.
  - 쌍은 **두 순서를 모두** 쓴다. M = 4면 12개, 3이면 6개, 2면 2개, 1이면 0개다.
  - 한 순서만 쓰면 채널 순서를 바꿨을 때 일부 쌍의 지연과 위치 부호가 뒤집힌다. 공유 인코더는 이를 다른 입력으로 받아들이므로, 테스트에서 실제로 출력이 달라졌다.
  - 쌍마다 같은 가중치를 쓰고 활성 쌍만 평균한다(TAC, `models/tac.py`). 그래서 가중치 하나로 어떤 M, 어떤 채널 순서든 받는다.
  - M = 1이면 공간 입력이 0이다. 그때는 Log-Mel만으로 가른다.

## 4. 구조 (`track_a` 약 2.3M 파라미터)

```
Log-Mel(4×80) ─ LayerNorm·Linear ─┐
                                  ├─ concat ─ Linear(144) ─ +위치 부호 ─ Conformer ×4 ─ 시점 판독 ─ Linear(128) ─ L2 정규화
GCC 쌍(4×33+2) ─ Linear ─ 쌍 TAC ×2 ─ 활성 쌍 평균 ┘
```

- **Conformer 블록**: d = 144, 헤드 4, FFN 576, 합성곱 커널 15.
- **정규화**: 배치 정규화 대신 LayerNorm을 쓴다. 배치의 다른 세션이 결과에 섞이지 않게 하려는 것이다.
- **크기 비교**: ECAPA 약 21M, VibeVoice-ASR 약 9B.

## 5. 학습

- **손실**: 기존 `SessionCentroidLoss`(같은 세션 안의 화자 중심 비교)를 최종 임베딩에 건다. 위치 손실은 없다. 공간 경로를 따로 떼어 학습하지 않는 단일 모델이기 때문이다.
- **채널 드롭**: `m_weights = (1, 1, 1, 1)`로 M = 1까지 학습한다. 체크포인트도 M = 1~4 평균으로 고른다(`select_min_M = 1`). 제안 모델은 M = 1에서 게이트가 구조상 0이라 M ≥ 2로 고른다.
- **예산**: 제안 모델과 같다. 20,000걸음, 배치 16, AdamW lr 1e-3, warm-up 500, 혼합 정밀도.

## 6. 설정 두 개

| 설정 | 입력 | 답하는 질문 |
|---|---|---|
| `track_a` | Log-Mel + GCC-PHAT | 사전학습 인코더 없이 작게 처음부터 만든 모델이 어디까지 가는가 |
| `track_a_spatial` | GCC-PHAT만 | 페이지의 "음색 특징 없이 위치 정보만으로". M = 1에서는 정보가 없으므로 한 화자로 몰린다 |

`track_a`는 Log-Mel로 목소리 단서를 스스로 배운다. 그래서 최종 검증 때 모든 화자를 한 위치에 둔 세션(`diagnostics.colocated`)도 함께 잰다. 그 점수가 목소리에서 얻은 몫이다.

## 7. 기존 코드에서 바꾼 것

- **실행 지문 보존**: `training/config.py`의 `track_a` 설정 묶음은 `model.name == "track_a"`일 때만 설정 사전에 들어간다. 그래서 다른 시스템의 실행 지문이 바뀌지 않는다. 지문이 바뀌면 학습 중인 실행이 이어 학습을 거부하고, 끝난 실행은 처음부터 다시 학습한다. 기존 설정 8개의 지문은 테스트로 고정했다.
- **학습 모델 판별**: `training/engine.py`와 `eval_t2.py`가 학습 모델을 `name == "proposed"`로 가르던 곳을 `trainable`(`TRAINED_SYSTEMS`) 기준으로 바꿨다.
  - 위치 손실은 공간 임베딩을 내는 모델에만 건다.
  - Track A는 ECAPA를 불러오지 않는다(`needs_voice`).
- **평가**: `eval_t2.py`의 Track A 변형은 `full`(causal)과 `full_context`(`full_audio`, M별 채점) 두 가지다.
- **노트북**: `train_template`의 `all`에 Track A 2종이 들어 있다. 다른 런타임에서 따로 학습할 때는 `all_track_a` 프리셋을 쓴다. `benchmark`의 `ours`와 `all_track_a`에도 들어 있다.

## 8. 확인한 것과 남은 것

- **확인**: CPU 스모크 학습과 본 평가 두 세션(가짜 음성, 6걸음)으로 학습 → 검증 두 모드 → 진단 → `eval_t2` 두 변형 → 완료 판정까지 돈다. 인과 모드는 10초 이후 오디오를 바꿔도 10초까지의 임베딩이 정확히 같다.
- **남음**: GPU 실제 학습. 걸음 속도와 시간은 첫 로그에서 확인한다.
