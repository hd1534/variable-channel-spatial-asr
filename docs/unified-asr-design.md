# Track C · 공간 통합 ASR 설계 (구현됨, 학습 전)

전사기 하나가 오디오와 마이크 공간 단서를 함께 받아 **누가 언제 무슨 말을 했는지 한 번에** 낸다.
구간을 잘라 전사하는 지금의 비교군 구조와 달리, 화자 구분과 전사가 한 모델 안에서 일어난다.
이름은 **Track C**다. Track A(초경량 Conformer, [track-a-design.md](track-a-design.md))와는 별개의 실험이다.

- 코드: [`trackc/`](../trackc) (`text.py`, `scenes.py`, `align.py`, `model.py`, `train.py`)
- 설정: [`configs/trackc/`](../configs/trackc) (`track_c`, `track_c_mono`, `smoke_real`, CPU 시험용 `smoke`)
- 노트북: [`notebooks/track_c.ipynb`](../notebooks/track_c.ipynb) (단어 정렬 → 학습·검증 → 본 평가 채점)
- 테스트: [`tests/test_track_c.py`](../tests/test_track_c.py). 모델 부분은 Qwen venv에서만 돌고, 아무것도 내려받지 않는 작은 무작위 Qwen3-ASR로 확인한다

## 0. 구현하며 정한 것

- **공간 특징을 넣는 자리**: `thinker.get_audio_features`를 감싸서, 인코더 출력에 어댑터 값을 더한다. 라이브러리는 고치지 않는다. 생성할 때도 프롬프트를 처리하는 첫 단계에 같은 값이 들어간다.
- **공간 인코더**: Track A와 같은 `models.track_a.PairSpatial`을 쓴다. 출력은 평균 풀링으로 오디오 토큰 수(20초에 260개)에 맞춘다.
- **판정 층의 시간 맞춤**: 인코더는 1초(멜 100프레임)마다 토큰 13개를 낸다. 토큰 중심 시각으로 0.25초 공식 창에 들어가는 토큰을 평균한다(`trackc.model.grid_pooling`).
- **학습 형식**: 공식 미세조정 스크립트와 같다. 접두부 `…language English<asr_text>`(언어 고정)와 패딩은 손실에서 뺀다(-100). 정답은 소문자 `[S1] … [S2] …`다(채점기가 대소문자와 구두점을 무시한다).
- **턴 자르기**: 정렬기의 단어 시각에서 0.08초 이상 빈 곳의 가운데에서만 자른다. 정렬기가 낸 단어 수가 전사문 단어 수와 다르면 그 발화를 쓰지 않는다. 세션 끝에서 잘린 턴이 생기면 그 세션을 다시 뽑는다.
- **최고 체크포인트**: 빠른 검증(40세션 × 마스크 3종)의 cpWER로 고른다. 최종 검증은 200세션 × 마스크 6종이다.
- **정렬기 고정**: `Qwen/Qwen3-ForcedAligner-0.6B` revision `c7cbfc2048c462b0d63a45797104fc9db3ad62b7`(Apache-2.0, 공개)를 쓴다.
- **환경**: `setup_asr_env.py --profile trackc`(`qwen-asr==0.0.6`, `peft==0.17.1`). 로컬에서 transformers 4.57.6과 함께 동작하는 것을 확인했다.

## 1. 바탕 모델: Qwen3-ASR-1.7B

공통 전사기와 같은 모델·같은 revision이다. `qwen-asr==0.0.6`, Apache-2.0.

| 항목 | 내용 (qwen-asr 0.0.6 소스와 기술 보고서 기준) |
|---|---|
| 오디오 인코더 | AuT, 약 300M. 24층, 폭 1024. 128구간 log-mel(100 프레임/초)을 받아 12.5 토큰/초로 줄인다. 20초는 약 260토큰이다 |
| 디코더 | Qwen3-1.7B, 28층, 폭 2048 |
| 오디오가 들어가는 곳 | 프롬프트의 오디오 자리 표시 토큰을 인코더 출력으로 바꿔 끼운다(`masked_scatter`). 공간 특징을 여기서 더한다 |
| 학습 | `model.thinker.forward(..., labels=...)`가 손실을 돌려준다. 공식 전체 미세조정 스크립트가 있다. LoRA는 공식 코드가 없어 `peft`를 직접 붙인다. 공개된 LoRA 미세조정은 모두 인코더를 동결하고 디코더에만 LoRA를 건다 |
| 인과성 | 인코더는 1~8초 창 안에서 양방향이다. 디코더는 인과다. **공식 causal 표에는 넣지 않고 `full_audio` 참고 행으로 보고한다** (VibeVoice·MOSS·Nemotron과 같은 조건) |

## 2. 구조

```
기준 채널 오디오 ─ log-mel ─ AuT 인코더(동결) ──────────────┐
                                                           (+) ─ 오디오 토큰 ─ Qwen3 디코더(+LoRA) ─┬─ 전사문
활성 마이크 쌍 GCC-PHAT ─ 쌍 TAC ─ 12.5 Hz로 줄임 ─ Linear(2048)·게이트(0에서 시작) ┘          └─ 판정 층 → 0.25초 격자 화자
```

- **공간 어댑터**: Track A와 같은 입력(마이크 쌍 GCC-PHAT와 쌍의 상대 위치)을 쓰고, 쌍마다 같은 가중치의 TAC로 묶는다. 출력을 오디오 토큰 길이에 맞춰 줄인 뒤 토큰마다 더한다.
  - 마지막 게이트를 0으로 초기화한다. 그래서 학습 시작 시점에는 원래 Qwen3-ASR과 똑같이 동작한다.
  - M = 1이면 쌍이 없어 더하는 값이 0이다. 그때는 목소리만으로 가른다.
- **전사문 형식**: 턴 순서대로 화자 표시를 붙인다. 표시 번호는 먼저 말한 사람이 1번이다.
  - 예: `language English<asr_text>[S1] so i went there [S2] did you see him [S1] no`
  - 새 어휘를 추가하지 않고 일반 텍스트 표시를 쓴다.
- **판정 층**: 디코더의 오디오 토큰 위치 은닉 상태(0.08초 간격)에서 `무음·S1·S2` 중 하나를 고른다. 이를 0.25초 격자로 모아 `Spk Acc`를 낸다.
  - 번호 규칙이 전사문과 같아서(먼저 말한 사람이 1번), 두 출력을 따로 맞출 필요가 없다.
  - 디코더는 오디오 토큰 사이에서 인과라서, 판정 층은 앞쪽 오디오만 보고 결정한다.

## 3. 학습 데이터

지금 학습 장면은 발화를 임의 위치에서 잘라 정답 텍스트가 없다. 그래서 평가셋 생성 방식으로 새 장면을 만든다.

1. **단어 정렬 (한 번만)**: `Qwen3-ForcedAligner-0.6B`(Apache-2.0, 단어 단위, 80 ms)로 `train-clean-100`과 `dev-clean`의 각 발화에 단어 시각을 붙인다. 결과는 색인 파일로 Drive에 백업한다.
2. **장면 생성 (학습 중 매번)**: 평가셋과 같은 규칙을 쓴다(`make_eval_t2.py`와 `training/scenes.py`에서 가져온다).
   - 화자 2명, 2~4턴. 화자마다 발화 하나를 단어 사이 쉼에서 잘라 턴으로 나눈다. 그래서 턴마다 정답 텍스트가 정확히 나온다.
   - 방은 기존 방 음향 뱅크(800개)를 쓰고, 위치 사본 이동, 확산 잡음 SNR 5~20 dB를 적용한다.
   - 마스크는 M = 1~4를 고르게 뽑는다.
3. **검증**: 기존 검증 세트 규칙(`dev-clean` 34명, 200세션)을 쓴다. 텍스트가 있는 같은 꼴로 새로 만든다.

학습 화자는 다른 시스템과 같은 251명이다. 평가 화자(`test-clean`)는 학습에 들어가지 않는다는 기존 검사를 그대로 쓴다.

## 4. 학습 설정

- **학습하는 것**: 공간 어댑터와 판정 층은 전부 학습한다. 디코더에는 LoRA(r = 16, 모든 선형층)를 건다. 인코더는 동결한다.
- **손실**: 전사문 교차 엔트로피 + λ × 판정 층 교차 엔트로피. λ는 1에서 시작한다.
- **최적화**: AdamW. LoRA·어댑터 lr 1e-4, warm-up 500, bf16, gradient checkpointing.
- **크기**: 배치 8, 약 10,000걸음.
  - 실제 메모리와 속도는 공개된 수치가 없다. Colab 짧은 실행으로 먼저 잰다.
  - A100 권장. L4는 배치를 줄여야 할 수 있다.
- **고르는 것**: 검증 `cpWER`와 `Spk Acc`로 최고 체크포인트를 고른다.

## 5. 설정 두 개 (공간 효과를 분리하기 위해)

| 설정 | 공간 어댑터 | 답하는 질문 |
|---|---|---|
| `unified_spatial` | 있음 | 공간 단서를 넣은 통합 모델이 어디까지 가는가 |
| `unified_mono` | 없음 (같은 데이터·같은 LoRA) | 같은 미세조정에서 공간 단서만 뺀 대조군. 두 설정의 차이가 곧 공간의 몫이다 |

미세조정 효과와 공간 효과가 섞이지 않게 하려면 `unified_mono`가 꼭 있어야 한다.
`unified_spatial`은 평가 때 공간 입력을 0으로 바꿔 한 번 더 재서, 모델이 실제로 공간을 쓰는지도 확인한다.

## 6. 평가

- **평가셋과 채점**: 같은 평가셋(`eval-t2`, `eval-t2-static`, 마스크 6종)을 공식 채점기로 채점한다. 관측 범위는 `full_audio`다.
- **출력 변환**: 출력을 Track B와 같은 기록 형식으로 바꿔 `track_b`의 채점 경로를 그대로 쓴다.
  - 판정 층 → 시점별 화자
  - 전사문 → 화자별 전사
- **비교 대상**:
  - VibeVoice·MOSS·Nemotron: 같은 `full_audio` 조건, 마이크 한 개
  - 공통 Qwen으로 구간 전사한 제안 모델: causal, 같은 전사기
- **보고 방법**: `benchmark.ipynb`에 시스템으로 추가한다. 웹페이지에는 `full_audio` 참고 행으로 둔다.

## 7. 작업 순서와 일정 (약 1~1.5주)

1. **정렬 색인**: 노트북 셀 하나로 만든다. Colab GPU로 한 번 돌린다.
2. **텍스트 있는 장면 생성기와 검증 세트**: CPU 테스트까지 한다.
3. **모델 래퍼**: 공간 어댑터 + LoRA + 판정 층. Mac CPU에서 짧은 오디오로 순전파·역전파가 되는지 확인한다(1.7B를 fp32로 쓰면 메모리 약 8 GB).
4. **학습 스크립트와 노트북**: 기존 체크포인트·백업 규칙(500걸음·10분, Drive 백업, 커밋 검사)을 따른다. Qwen 전용 venv에서 돈다.
5. **Colab 짧은 실행**: 메모리와 속도를 재고, 그 수치로 걸음 수와 GPU를 정한다.
6. **본 학습**: 두 설정을 다른 런타임에서 동시에 돌릴 수 있다.
7. **본 평가, 웹페이지·BENCHMARK.md 반영**

## 8. 위험

| 위험 | 대응 |
|---|---|
| 251명·약 100시간으로는 목소리 기반 구분이 약할 수 있다 | `unified_mono`와 비교해 공간의 몫을 그대로 보고한다. 약하면 약하다고 쓴다 |

| `qwen-asr` 0.0.6이 transformers 4.57.6을 고정한다 | 기존 Qwen 전용 venv에 `peft`만 추가한다. 버전은 고정해 기록한다 |
| 학습 메모리와 시간을 모른다 | 5단계 짧은 실행에서 재고, 결과에 따라 배치·걸음 수를 정한다 |
| 실패 시 남는 것이 없다 | Track A는 별개라 영향을 받지 않는다. 지금 학습 중인 제안 모델·벤치도 그대로다 |

## 9. 확인한 것과 남은 것

- **확인 (CPU)**: 작은 무작위 Qwen3-ASR로 다음을 확인했다.
  - 학습 손실의 기울기가 LoRA·어댑터·판정 층에만 가고 인코더에는 가지 않는다.
  - 학습 전 어댑터는 전사를 바꾸지 않는다.
  - 마이크가 하나면 공간 값이 0이다.
  - 생성 결과로 텍스트와 80시점 판정이 나온다.
  - 학습 → 체크포인트 → 이어 학습 → 검증 → 요약 → 본 평가(M별, `no_space` 변형 포함)까지 돈다.
- **남은 것**: 실제 1.7B 모델과 실제 처리기(processor)로 도는지는 Colab `smoke_real`로 확인한다. 메모리·속도도 그때 잰다. 단어 정렬에서 단어 수가 맞지 않아 버려지는 발화의 비율도 그때 본다.
